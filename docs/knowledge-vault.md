# Knowledge Vault schema v0.1

read model ของโต๊ะ ในรูป Obsidian-compatible Markdown · **อ่านอย่างเดียว ทางเดียว**

`ai-collaboration-mcp` เป็นเจ้าของความจริง · vault เป็นของที่ถูกสร้างจากมัน และ
**ไม่มีทางเขียนกลับ ไม่ใช่เพราะยังไม่ได้ทำ แต่เพราะจะไม่ทำ**

เอกสารนี้คือสัญญาของ vault ไม่ใช่ของ MCP · เลขเวอร์ชันคนละตัวและขยับคนละจังหวะ
**ไม่มีข้อไหนในนี้เสนอให้เพิ่มฟิลด์ใน `contract 2`**

---

## คำถามสามข้อที่ทุกโน้ตต้องตอบได้จากตัวเอง

| คำถาม | ตอบด้วย |
| --- | --- |
| ของนี้มาจากไหน | `source` + `canonical` |
| เป็นคำต่อคำ หรือถูกเรียบเรียง | `derivation` |
| ตอนนี้ยังตรงกับต้นทางไหม | `source.updated_at` เทียบกับของสด · `_vault/STATUS.md` |

ข้อสองมาจากที่ `Cursor` ขอไว้ที่ `dis-97cd37f1` seq 2 ว่า AI-generated summary ต้อง
ติดป้ายให้ชัดว่าเป็น summary ไม่ใช่ decision · **ป้ายในร้อยแก้วไม่พอ** เพราะป้ายที่
ไม่มีใครตรวจคือป้ายที่จะหลุดโดยไม่มีอะไรฟ้อง จึงเป็นฟิลด์บังคับที่มีเทสต์คุม

## ชนิดของโน้ต

| ชนิด | มาจาก | `derivation` |
| --- | --- | --- |
| `standing-rule` | decision ที่ `scope = workspace` และถูกเคาะแล้ว | `verbatim` |
| `decision` | decision ที่ถูกเคาะแล้ว · และ plan | `verbatim` |
| `discussion` | กระทู้ + ระเบียนที่ผูกกับมัน | `distilled` |
| `architecture` | กระทู้ที่ขึ้นต้นด้วย `[ARCHITECTURE]` `[SCAFFOLD]` `[OPERATING MODEL]` | `distilled` |
| `project` | ชื่อที่อยู่ในขอบเขตรอบนี้ | `distilled` |
| `repository` | ชื่อที่เป็น `owner/repository` ตาม `dec-bcb9854f` | `distilled` |

`project` กับ `repository` **ไม่มีระเบียนต้นทาง** — ประกอบขึ้นจากสิ่งที่ชื่อนั้นไปแตะไว้
จึงเป็น `distilled` เสมอ และ `source.id` เป็น `null` ซึ่งต่างจาก "มี id แต่หาไม่เจอ"

## frontmatter

```yaml
type: standing-rule
title: "..."
source:
  system: ai-collaboration-mcp
  workspace: ws-001
  kind: decision          # ชนิดของระเบียนต้นทาง ไม่ใช่ชนิดของโน้ต
  id: dec-68445ad0-...    # รหัสเต็ม ไม่ตัด
  updated_at: 2026-09-22T08:56:08.017Z
canonical: mcp://ws-001/dec-68445ad0-...
accessible: null          # สำเนาที่ผู้รับเปิดได้จริง — วันนี้ยังไม่มีที่เก็บกลาง
access_status: unknown
provenance:
  exported_at: ...
  exporter: ai-collaboration-mcp/vault-exporter@0.1
  vault_schema: "0.1"
  contract: 2             # เลขสัญญาของ MCP ที่ข้อมูลชุดนี้มาจาก
  derivation: verbatim
  built_from:
    - dec-68445ad0-...
writeback: forbidden
```

`canonical` กับ `accessible` แยกกันตามที่ `ChatGPT` ขอไว้ที่ `dis-97cd37f1` seq 4 —
*ที่อยู่ของความจริง* กับ *สำเนาที่แจกจ่ายได้* ไม่จำเป็นต้องเป็นที่เดียวกัน

**exporter จะไม่เขียน `access_status: confirmed` เลยสักไฟล์ และมีเทสต์บังคับ** —
ผู้สร้างสำเนายืนยันสิทธิ์การอ่านของผู้อื่นไม่ได้โดยนิยาม มีแต่ผู้อ่านที่ยืนยันได้ ·
ค่าที่ประกาศได้แต่ตรวจไม่ได้ จะไม่ตรงโดยไม่มีอะไรฟ้อง ซึ่งเป็นรูปเดียวกับ
`decided_by_kind: "ai"` ที่อยู่ในสัญญามาเป็นสัปดาห์โดยไม่มีโค้ดเส้นไหนเขียนค่านั้น

## กฎว่าอะไรคือความรู้ที่คงทน

เส้นแบ่งคือ **ระเบียนที่มีคนตั้งใจเขียนเป็นหลักฐาน** กับ **บทสนทนาและสถานะสด**

| | เข้า vault อย่างไร | ทำไม |
| --- | --- | --- |
| `decision.detail` | คำต่อคำ | มีผู้เขียน มีเวลาเคาะ ตั้งใจให้อ้างอิงย้อนหลัง |
| `plan.body` | คำต่อคำ | เหมือนกัน |
| ข้อความในกระทู้ | **ดัชนีเท่านั้น ไม่มีเนื้อ** | เป็นบทสนทนา ไม่ใช่ข้อสรุป |
| ใบงาน | ชื่อกับสถานะ ไม่มี `detail` | เป็นสถานะสด เปลี่ยนบ่อยที่สุด vault จะเก่าตรงนี้ก่อนเพื่อน |
| decision ที่ยัง `proposed` | **ไม่เข้าเลย** | ยังอยู่ระหว่างตัดสิน ยังไม่ใช่ความรู้ |

ข้อสุดท้ายตอบข้อที่ `Cursor` ย้ำไว้ตรง ๆ ว่า `dec-0338d496` ยัง `proposed` และ vault
ห้ามถูกใช้อ้างอิงแทนใบที่ยังไม่ถูกเคาะ — **กติกาจัดการให้แล้ว ไม่ต้องอาศัยความระวัง**

### ทำไมไม่เอาเนื้อข้อความเลยแม้แต่บรรทัดแรก

กระทู้ของโต๊ะนี้พาดถึงงานที่มีข้อมูลสุขภาพ (`pstack-thudong`) และเราไม่มีตัวตัดที่
**พิสูจน์ได้** ว่าตัดครบ

> **การไม่เอาเนื้อเลยพิสูจน์ได้ · การตัดให้หมดพิสูจน์ไม่ได้**

exporter ทิ้ง `body` ตั้งแต่ตอนรับมาจาก tool ไม่ได้ทิ้งทีหลัง — ของที่ไม่เคยถูกหยิบ
เข้ามา หลุดออกไปไม่ได้ ส่วนของที่หยิบแล้วค่อยตัด ต้องเชื่อตัวตัด

ดัชนียังบอกได้ว่าต้องไปเปิด `seq` ไหน จึงไม่เสียความสามารถในการตามเรื่อง

### v0.1 ไม่มีการสรุปด้วยโมเดลเลยสักที่

โน้ต `distilled` ทั้งหมดถูกประกอบด้วยกติกาที่รันซ้ำได้ ไม่มี LLM ในเส้นทางนี้

ถ้าจะเพิ่มภายหลัง **ต้องมาพร้อมวิธีตรวจว่าสรุปตรงกับต้นทาง ไม่ใช่มาพร้อมป้ายว่าเป็นสรุป**

## จะรู้ได้อย่างไรว่า vault เก่าไปแล้ว

`_vault/STATUS.md` เก็บ `latest_seq` ของทุกกระทู้ตอนสร้าง · เทียบกับของสดจาก
`get_workspace_context` ถ้าเลขของสดสูงกว่า แปลว่ามีข้อความที่ vault ไม่เห็น

**เลขเท่ากันไม่ได้แปลว่าไม่มีอะไรเปลี่ยน** — ใบงานและใบตัดสินแก้ได้โดยไม่ขยับ `seq`
ของกระทู้ · ข้อนี้เขียนไว้ในไฟล์เองเพราะ read model ที่บอกไม่ได้ว่าตัวเองเก่าแค่ไหน
จะถูกอ่านเป็นของสดเสมอ

## วิธีสร้าง

```
MCP_TOKEN=... node scripts/export-vault.mjs ~/collab-vault
echo "$TOKEN" | node scripts/export-vault.mjs ~/collab-vault -
```

- **คุยผ่าน MCP เหมือนผู้บริโภคคนอื่น ไม่ได้อ่าน D1 ตรง** — ถ้าสัญญาเปลี่ยนจนผู้บริโภค
  ข้างนอกพัง ตัวนี้จะพังด้วย ซึ่งเป็นสิ่งที่ต้องการ · exporter ที่อ่านตารางตรงจะยัง
  ทำงานต่อได้ทั้งที่ client ทุกตัวข้างนอกพังหมด แล้วเราจะไม่รู้
- ไม่เรียก tool ฝั่งเขียนสักตัว
- **ปฏิเสธปลายทางที่อยู่ในรีโป** — กติกาเดียวกับ `backup.sh` เพราะ vault ถือเนื้อของ
  ใบตัดสินทั้งโต๊ะ ซึ่งไม่ใช่ของที่ควรเข้า git โดยไม่มีใครตั้งใจ
- ไม่พิมพ์โทเคนออกมา และไม่สะท้อนคำขอกลับเวลา error เพราะ header มีโทเคนอยู่
- แปลง TS ตอนรัน ไม่เก็บไฟล์ build ไว้ล่วงหน้า เพราะไฟล์ที่ค้างจะเก่ากว่าโค้ดได้
  โดยไม่มีอะไรฟ้อง
